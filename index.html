Tanulói szabály: az OVA-fájl nevét ne módosítsd, és a kiinduló gépen ne készíts saját hálózati „javítást” a feladat előtt. Ha a letöltéshez ellenőrzőösszeg van megadva, Windows alatt a certutil -hashfile FÁJLNÉV.ova SHA256 paranccsal ellenőrizd.

Rocky OVA importálása

  1. VirtualBox → File → Import Appliance.
  2. Válaszd ki a Rocky Linux OVA-t.
  3. Import után még ne indítsd el.
  4. Settings → Network: Adapter 1 = NAT.
  5. Adapter 2 = Internal Network, neve pontosan LABNET.
  6. Mindkét adapteren legyen aktív a Cable Connected.

Windows 7 OVA importálása

  1. File → Import Appliance → Windows 7 x86 OVA.
  2. Settings → Network.
  3. Adapter 1 = Internal Network.
  4. Hálózat neve: LABNET.
  5. A Windows kliensnek ebben a laborban nincs szüksége internetre.
  6. A DHCP modulig ideiglenes statikus címet használunk.
Miért jó az OVA? Minden tanuló ugyanarról az ellenőrzött állapotról indul. Így az óra a szerverüzemeltetésről szól, nem az operációs rendszer telepítéséről. Az OVA ugyanakkor csak a kiindulópont: a DHCP, DNS, FTP, HTTP és jogosultsági feladatokat neked kell elkészítened.

Egymásra épülő gyakorlati modulok

1. modul • 45 perc • K01–K03

Rendszerfelmérés és VirtualBox-hálózat

Elmélet: a NAT és az Internal Network két külön feladatot lát el. A NAT kifelé biztosít internetet a szervernek, az Internal Network pedig a Rocky és a Windows kliens izolált laborhálózata.

1. Azonosítsd a Rocky rendszert

cat /etc/rocky-release hostnamectl uname -r
Akkor jó: Rocky Linux 10.2 látható.

2. Keresd meg a hálózati interfészeket

ip -br link ip -br address nmcli device status nmcli connection show

A neveket ne feltételezd. Lehet például enp0s3 és enp0s8, de mindig a saját géped kimenetét használd.

3. NAT ellenőrzése

ip route ping -c 3 1.1.1.1
K01: verzió + hostname • K02: két interfész • K03: sikeres NAT ping.
2. modul • 45 perc • K04–K07

Statikus LABNET IP, SSH és PuTTY

Elmélet: a szerver belső címe statikus, hogy a kliensek mindig ugyanazon az IP-n találják a DHCP/DNS/FTP/HTTP szolgáltatásokat.

1. LABNET kapcsolat létrehozása

Az enp0s8 helyére a saját belső interfészed nevét írd.

sudo nmcli connection add type ethernet ifname enp0s8 con-name LABNET \ ipv4.method manual ipv4.addresses 192.168.50.1/24 \ ipv6.method disabled sudo nmcli connection modify LABNET connection.zone internal sudo nmcli connection up LABNET ip -br address ip route
Akkor jó: a LABNET interfészen 192.168.50.1/24 van, külön default gateway nélkül.

2. SSH és tűzfal

sudo systemctl enable --now sshd sudo firewall-cmd --permanent --zone=internal --add-service=ssh sudo firewall-cmd --reload sudo firewall-cmd --zone=internal --list-all

3. Windows 7 ideiglenes címe

  • IP: 192.168.50.10
  • Maszk: 255.255.255.0
  • Átjáró: üres
  • DNS: egyelőre üres
ipconfig ping 192.168.50.1

4. PuTTY

  1. Host: 192.168.50.1, port 22, SSH.
  2. Fogadd el az első host key figyelmeztetést.
  3. Felhasználó: student; jelszó: a tanár adja meg.
  4. Belépés után: whoami, hostname, ip -br address.
K04: LABNET IP • K05: Windows ping • K06: PuTTY login • K07: SSH firewalld.
3. modul • 45 perc • K08–K11

Felhasználók, csoportok és jogosultságok

Elmélet: a Linux fájlhozzáférést a tulajdonos, a csoport és az others jogai szabályozzák. Könyvtárnál az x a belépést/útvonalon áthaladást jelenti.

1. Felhasználók és projekt csoport

sudo groupadd projekt sudo useradd -m anna sudo useradd -m bela sudo useradd -m vendeg sudo usermod -aG projekt anna sudo usermod -aG projekt bela sudo passwd anna sudo passwd bela sudo passwd vendeg id anna id bela id vendeg

2. Labor könyvtárstruktúra

sudo mkdir -p /srv/ftp/{anna,bela,kozos,nyilvanos} sudo chown root:root /srv/ftp && sudo chmod 755 /srv/ftp sudo chown anna:anna /srv/ftp/anna && sudo chmod 700 /srv/ftp/anna sudo chown bela:bela /srv/ftp/bela && sudo chmod 700 /srv/ftp/bela sudo chown root:projekt /srv/ftp/kozos && sudo chmod 2770 /srv/ftp/kozos sudo chown root:root /srv/ftp/nyilvanos && sudo chmod 755 /srv/ftp/nyilvanos

3. Jogok értelmezése

ls -ld /srv/ftp /srv/ftp/* stat -c '%A %a %U %G %n' /srv/ftp/* namei -l /srv/ftp/kozos

4. Pozitív és negatív teszt

sudo -u anna touch /srv/ftp/anna/anna.txt sudo -u anna touch /srv/ftp/kozos/anna-kozos.txt sudo -u bela touch /srv/ftp/kozos/bela-kozos.txt sudo -u vendeg touch /srv/ftp/kozos/vendeg.txt ls -l /srv/ftp/kozos
Akkor jó: anna és bela írhat a közös mappába, vendeg pedig Permission denied hibát kap.
K08: id • K09: jogosultságok • K10: tiltott írás • K11: setgid/projekt csoport.
4. modul • 45 perc • K12–K15

Kea DHCPv4 – automatikus Windows-cím

Elmélet: DHCP automatikusan ad IP-konfigurációt a kliensnek. Rocky Linux 10-ben a Kea váltotta a régi ISC DHCP szervert.

1. Telepítés

sudo dnf -y install kea rpm -q kea sudo cp /etc/kea/kea-dhcp4.conf /etc/kea/kea-dhcp4.conf.orig

2. /etc/kea/kea-dhcp4.conf

{ "Dhcp4": { "interfaces-config": { "interfaces": [ "enp0s8" ] }, "valid-lifetime": 3600, "renew-timer": 900, "rebind-timer": 1800, "option-data": [ { "name": "domain-name", "data": "lab.test" }, { "name": "domain-name-servers", "data": "192.168.50.1" } ], "subnet4": [ { "id": 1, "subnet": "192.168.50.0/24", "pools": [ { "pool": "192.168.50.100 - 192.168.50.150" } ] } ] } }

Fontos: az enp0s8 helyére a saját LABNET interfészed neve kerüljön.

3. Ellenőrzés, tűzfal, indítás

sudo kea-dhcp4 -t /etc/kea/kea-dhcp4.conf sudo firewall-cmd --permanent --zone=internal --add-service=dhcp sudo firewall-cmd --reload sudo systemctl enable --now kea-dhcp4 sudo systemctl status kea-dhcp4 --no-pager

4. Windows 7 vissza DHCP-re

IPv4: IP és DNS automatikus, majd CMD:

ipconfig /release ipconfig /renew ipconfig /all
169.254.x.x? A Windows nem kapott DHCP-választ. Vizsgáld: LABNET név, Kea interfésznév, szolgáltatás állapota és firewalld.
K12: syntax check • K13: active Kea • K14: DHCP-s Windows • K15: Kea napló.
5. modul • 45 perc • K16–K19

BIND DNS – saját belső névtér

Elmélet: a DNS név és IP-cím között teremt kapcsolatot. A forward zóna A rekordokat, a reverse zóna PTR rekordokat használ.

1. Telepítés

sudo dnf -y install bind bind-utils sudo cp /etc/named.conf /etc/named.conf.orig

2. /etc/named.conf – options releváns beállításai

listen-on port 53 { 127.0.0.1; 192.168.50.1; }; allow-query { localhost; 192.168.50.0/24; }; recursion yes; forwarders { 1.1.1.1; 8.8.8.8; };

3. Zónák

Az /etc/named.rfc1912.zones végére:

zone "lab.test" IN { type master; file "lab.test.zone"; allow-update { none; }; }; zone "50.168.192.in-addr.arpa" IN { type master; file "50.168.192.rev"; allow-update { none; }; };

4. Forward zóna: /var/named/lab.test.zone

$TTL 1H @ IN SOA server.lab.test. admin.lab.test. ( 2026101601 1H 15M 1W 1H ) IN NS server.lab.test. server IN A 192.168.50.1 www IN A 192.168.50.1 ftp IN A 192.168.50.1

5. Reverse zóna: /var/named/50.168.192.rev

$TTL 1H @ IN SOA server.lab.test. admin.lab.test. ( 2026101601 1H 15M 1W 1H ) IN NS server.lab.test. 1 IN PTR server.lab.test.

6. Jogok, ellenőrzés, indítás

sudo chown root:named /var/named/lab.test.zone /var/named/50.168.192.rev sudo chmod 640 /var/named/lab.test.zone /var/named/50.168.192.rev sudo restorecon -v /var/named/lab.test.zone /var/named/50.168.192.rev sudo named-checkconf sudo named-checkzone lab.test /var/named/lab.test.zone sudo named-checkzone 50.168.192.in-addr.arpa /var/named/50.168.192.rev sudo firewall-cmd --permanent --zone=internal --add-service=dns sudo firewall-cmd --reload sudo systemctl enable --now named

7. Teszt

dig @192.168.50.1 www.lab.test +short dig @192.168.50.1 -x 192.168.50.1 +short

Windows 7:

ipconfig /flushdns nslookup server.lab.test nslookup www.lab.test nslookup ftp.lab.test ping server.lab.test
K16: named-check • K17: dig • K18: nslookup • K19: név szerinti ping.
6. modul • 45 perc • K20–K24

vsftpd – FTP és valódi jogosultságteszt

Elmélet: az FTP itt oktatási célú, izolált LABNET hálózaton fut. Azért használjuk, mert jól láthatóvá teszi, hogyan érvényesülnek hálózaton keresztül a Linux user/group/others jogosultságok. Éles környezetben inkább SFTP-t használunk.

1. Telepítés és mentés

sudo dnf -y install vsftpd sudo cp /etc/vsftpd/vsftpd.conf /etc/vsftpd/vsftpd.conf.orig

2. /etc/vsftpd/vsftpd.conf

listen=YES listen_ipv6=NO anonymous_enable=NO local_enable=YES write_enable=YES local_umask=002 dirmessage_enable=YES use_localtime=YES xferlog_enable=YES connect_from_port_20=YES chroot_local_user=YES local_root=/srv/ftp pasv_enable=YES pasv_min_port=30000 pasv_max_port=30100 pam_service_name=vsftpd userlist_enable=YES

3. SELinux laborbeállítás

getenforce getsebool -a | grep ftpd sudo setsebool -P ftpd_full_access on getsebool ftpd_full_access
Oktatási kompromisszum: ebben a zárt laborban az FTP-hozzáférést elsősorban a Unix jogosultságok vizsgálatához egyszerűsítjük. SELinux maradjon Enforcing módban.

4. Tűzfal és szolgáltatás

sudo firewall-cmd --permanent --zone=internal --add-service=ftp sudo firewall-cmd --permanent --zone=internal --add-port=30000-30100/tcp sudo firewall-cmd --reload sudo systemctl enable --now vsftpd sudo systemctl status vsftpd --no-pager sudo ss -lntp | grep :21

5. Windows FTP – anna

Hozz létre az Asztalon egy anna-win.txt fájlt.

ftp ftp.lab.test

Az FTP promptban:

dir cd anna put anna-win.txt cd .. cd kozos put anna-win.txt cd .. cd bela quit
Akkor jó: anna saját és közös mappába írhat, bela mappájába nem.

6. vendeg negatív teszt + Rocky ellenőrzés

vendeg a nyilvános tartalmat olvashatja, a közös mappába viszont ne tudjon írni.

sudo find /srv/ftp -maxdepth 2 -type f -printf '%M %u %g %p\n' sudo journalctl -u vsftpd --since "15 minutes ago" --no-pager
K20: vsftpd/21 • K21: anna saját • K22: anna közös • K23: tiltás • K24: tulajdonos/csoport.
7. modul • 45 perc • K25–K27

Apache webszolgáltatás és saját státuszoldal

Elmélet: az Apache HTTP Server a 80/TCP porton szolgál ki tartalmat. A DNS miatt a kliens az IP helyett a www.lab.test nevet használhatja.

1. Telepítés és tűzfal

sudo dnf -y install httpd sudo systemctl enable --now httpd sudo firewall-cmd --permanent --zone=internal --add-service=http sudo firewall-cmd --reload sudo systemctl status httpd --no-pager

2. Saját oldal: /var/www/html/index.html

<!doctype html> <html lang="hu"> <head><meta charset="utf-8"><title>Rocky Linux labor</title></head> <body> <h1>Rocky Linux 10.2 szerverlabor</h1> <p>Készítette: SAJÁT NÉV</p> <ul> <li>DHCP – Kea</li> <li>DNS – BIND</li> <li>FTP – vsftpd</li> <li>SSH – OpenSSH</li> <li>HTTP – Apache</li> </ul> </body></html>

curl http://127.0.0.1 curl http://www.lab.test

8. modul • 45 perc • K28–K30

firewalld, hibakísérlet és integrált ellenőrzés

Elmélet: attól, hogy egy daemon fut, a kliens még nem biztos, hogy eléri. A teljes útvonal: kliens → IP/hálózat → DNS → tűzfal → hallgató port → daemon → alkalmazás.

1. Végleges internal zóna

sudo firewall-cmd --get-active-zones sudo firewall-cmd --zone=internal --list-all

Várható szolgáltatások: ssh dhcp dns ftp http, továbbá FTP passzív portok: 30000-30100/tcp.

2. Tudatos HTTP hibakísérlet

sudo firewall-cmd --zone=internal --remove-service=http

Windows böngészőben frissítsd a weboldalt: most ne legyen elérhető. Ezután:

sudo firewall-cmd --zone=internal --add-service=http

Frissíts újra: működjön.

3. Szolgáltatás- és portellenőrzés

systemctl --no-pager --type=service --state=running | grep -E 'sshd|kea-dhcp4|named|vsftpd|httpd' sudo ss -lntup | grep -E ':22|:21|:53|:67|:80'

4. Végső Windows teszt

ipconfig /all ping server.lab.test nslookup www.lab.test nslookup ftp.lab.test
  • PuTTY → server.lab.test
  • FTP → ftp.lab.test
  • Böngésző → http://www.lab.test

5. Hibakeresési sorrend

1. IP?→2. Ping?→3. DNS?→4. active?→5. port?→6. tűzfal?→7. log?
K28: teljes firewalld • K29: HTTP tiltás/visszaállítás • K30: integrált Windows teszt.
