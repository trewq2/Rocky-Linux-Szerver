1. modul • 45 perc

Rendszerfelmérés és VirtualBox-hálózat

Elmélet: a NAT és az Internal Network két külön szerepet kap. A NAT kifelé biztosít kapcsolatot a Rocky szervernek. Az Internal Network egy izolált virtuális kapcsoló, amelyen a Rocky és a Windows kliens egymással kommunikál.

1. Jelentkezz be a Rocky szerverre

A tanári RAW OVA alapértelmezett admin felhasználója: student. A jelszót a tanár adja meg.

2. Azonosítsd a rendszert

cat /etc/rocky-release hostnamectl uname -r
Akkor jó: Rocky Linux 10.2 és egy 64 bites kernel látható.

3. Azonosítsd a két hálózati interfészt

ip -br link ip -br address nmcli device status nmcli connection show

VirtualBoxban gyakori nevek: enp0s3 = NAT és enp0s8 = belső hálózat, de a saját gépeden látható nevet használd.

Jegyezd fel: NAT interfész neve: ________    Belső interfész neve: ________

4. Bizonyítsd, hogy a NAT működik

ip route ping -c 3 1.1.1.1
Ha nincs internet: ellenőrizd VirtualBoxban az Adapter 1 = NAT és Cable Connected állapotot, majd nmcli device.
K01: Rocky 10.2 verzió és hostname.
K02: ip -br address a két interfésszel.
K03: sikeres ping a NAT interfészen keresztül.
2. modul • 45 perc

Statikus belső IP, SSH és PuTTY

Elmélet: szervereken a kiszolgálói interfész címe jellemzően statikus. A klienseknek tudniuk kell, hogy a DNS/DHCP/FTP/HTTP szerver mindig ugyanazon a címen található.

1. Hozd létre a LABNET kapcsolatot

A következő parancsban az enp0s8 helyére a saját belső interfészed nevét írd:

sudo nmcli connection add type ethernet ifname enp0s8 con-name LABNET \ ipv4.method manual ipv4.addresses 192.168.50.1/24 \ ipv6.method disabled
sudo nmcli connection modify LABNET connection.zone internal sudo nmcli connection up LABNET ip -br address ip route
Akkor jó: a belső interfészen 192.168.50.1/24 látható, de azon nincs default gateway.

2. SSH szolgáltatás

sudo systemctl enable --now sshd sudo systemctl status sshd --no-pager sudo firewall-cmd --permanent --zone=internal --add-service=ssh sudo firewall-cmd --reload sudo firewall-cmd --zone=internal --list-all

3. Windows 7 ideiglenes statikus cím

A DHCP még nincs kész, ezért a Windows 7 kliensen ideiglenesen állíts be:

  • IP: 192.168.50.10
  • Maszk: 255.255.255.0
  • Átjáró: üres
  • DNS: egyelőre üres

Windows CMD:

ipconfig ping 192.168.50.1

4. PuTTY kapcsolat

  1. Indítsd el a PuTTY-t Windows 7-en.
  2. Host Name: 192.168.50.1
  3. Port: 22, Connection type: SSH.
  4. Open → fogadd el az első host key figyelmeztetést.
  5. Jelentkezz be student felhasználóval.
whoami hostname ip -br address
K04: Rocky LABNET IP.
K05: Windows ping 192.168.50.1-re.
K06: PuTTY ablak sikeres student bejelentkezéssel.
K07: firewalld internal zóna SSH szolgáltatással.

Felhasználók, csoportok és Linux jogosultságok

Elmélet: minden fájlnak van tulajdonosa, csoportja és három jogosultságcsoportja: owner, group, others. Könyvtárnál az x azt jelenti, hogy be lehet lépni / útvonalon keresztül lehet haladni.

1. Felhasználók és csoport

sudo groupadd projekt sudo useradd -m anna sudo useradd -m bela sudo useradd -m vendeg sudo usermod -aG projekt anna sudo usermod -aG projekt bela id anna id bela id vendeg

Állíts be a tanár által megadott jelszót mindhárom felhasználónak:

sudo passwd anna sudo passwd bela sudo passwd vendeg

2. FTP-labor könyvtárstruktúra

sudo mkdir -p /srv/ftp/{anna,bela,kozos,nyilvanos} sudo chown root:root /srv/ftp sudo chmod 755 /srv/ftp sudo chown anna:anna /srv/ftp/anna sudo chmod 700 /srv/ftp/anna sudo chown bela:bela /srv/ftp/bela sudo chmod 700 /srv/ftp/bela sudo chown root:projekt /srv/ftp/kozos sudo chmod 2770 /srv/ftp/kozos sudo chown root:root /srv/ftp/nyilvanos sudo chmod 755 /srv/ftp/nyilvanos sudo touch /srv/ftp/nyilvanos/OLVASS_EL.txt echo "Ez a nyilvanos labor konyvtar." | sudo tee /srv/ftp/nyilvanos/OLVASS_EL.txt

3. Értelmezd a jogosultságokat

ls -ld /srv/ftp /srv/ftp/* namei -l /srv/ftp/kozos stat -c '%A %a %U %G %n' /srv/ftp/*
Figyeld meg: a 2770 elején lévő 2 setgid bit. A közös mappában létrejövő fájlok csoportja öröklődik.

4. Jogosultságteszt parancssorból

sudo -u anna touch /srv/ftp/anna/anna.txt sudo -u anna touch /srv/ftp/kozos/anna-kozos.txt sudo -u bela touch /srv/ftp/kozos/bela-kozos.txt sudo -u vendeg touch /srv/ftp/kozos/vendeg.txt ls -l /srv/ftp/kozos
Akkor jó: anna és bela tud írni a közös mappába, vendeg pedig Permission denied hibát kap. Ez most kívánt eredmény.
K08: id kimenetek.
K09: könyvtárjogosultságok numerikus és rwx formában.
K10: vendeg sikertelen írása.
K11: anna és bela fájljai a közös mappában, projekt csoporttal.
4. modul • 45 perc

Kea DHCPv4 – a Windows kliens automatikus címet kap

Elmélet: DHCP a DORA folyamatban címet ajánl és ad a kliensnek. Rocky Linux 10-ben a modern Kea DHCP-szervert használjuk.

1. Kea telepítése

sudo dnf -y install kea rpm -q kea sudo systemctl status kea-dhcp4 --no-pager

2. Konfiguráció

Először mentsd az eredetit:

sudo cp /etc/kea/kea-dhcp4.conf /etc/kea/kea-dhcp4.conf.orig

Nyisd meg:

sudo nano /etc/kea/kea-dhcp4.conf

Írd be az alábbi konfigurációt. Az enp0s8 helyére a saját LABNET interfészed neve kerüljön:

{ "Dhcp4": { "interfaces-config": { "interfaces": [ "enp0s8" ] }, "valid-lifetime": 3600, "renew-timer": 900, "rebind-timer": 1800, "option-data": [ { "name": "domain-name", "data": "lab.test" }, { "name": "domain-name-servers", "data": "192.168.50.1" } ], "subnet4": [ { "id": 1, "subnet": "192.168.50.0/24", "pools": [ { "pool": "192.168.50.100 - 192.168.50.150" } ] } ] } }

3. Ellenőrzés és indítás

sudo kea-dhcp4 -t /etc/kea/kea-dhcp4.conf sudo firewall-cmd --permanent --zone=internal --add-service=dhcp sudo firewall-cmd --reload sudo systemctl enable --now kea-dhcp4 sudo systemctl status kea-dhcp4 --no-pager

4. Windows 7 átállítása DHCP-re

  1. IPv4 tulajdonságok → Obtain an IP address automatically.
  2. DNS → Obtain DNS server address automatically.
  3. CMD:
ipconfig /release ipconfig /renew ipconfig /all
Akkor jó: a Windows címe 192.168.50.100–150 közé esik, DNS-kiszolgálója 192.168.50.1, DNS suffixe lab.test.
Ha 169.254.x.x címet kapsz: nincs DHCP válasz. Ellenőrizd: LABNET hálózatnév, interfésznév a Kea fájlban, systemctl status kea-dhcp4, és a firewalld DHCP szabály.
K12: sikeres Kea syntax check.
K13: kea-dhcp4 active állapot.
K14: Windows ipconfig /all DHCP-címmel.
K15: journalctl -u kea-dhcp4 részlet, amely kliensműveletet mutat.

BIND DNS – saját belső névtér

Elmélet: a DNS név → IP feloldást végez. A forward zóna A rekordokat, a reverse zóna PTR rekordokat tartalmaz. A labor saját zónája: lab.test.

1. BIND telepítése

sudo dnf -y install bind bind-utils sudo cp /etc/named.conf /etc/named.conf.orig

2. named.conf

Nyisd meg: sudo nano /etc/named.conf. Az options blokkban a lényeg legyen:

listen-on port 53 { 127.0.0.1; 192.168.50.1; }; allow-query { localhost; 192.168.50.0/24; }; recursion yes; forwarders { 1.1.1.1; 8.8.8.8; };

3. Zónák felvétele

Az /etc/named.rfc1912.zones végére:

zone "lab.test" IN { type master; file "lab.test.zone"; allow-update { none; }; }; zone "50.168.192.in-addr.arpa" IN { type master; file "50.168.192.rev"; allow-update { none; }; };

4. Forward zóna

sudo nano /var/named/lab.test.zone
$TTL 1H @ IN SOA server.lab.test. admin.lab.test. ( 2026101401 1H 15M 1W 1H ) IN NS server.lab.test. server IN A 192.168.50.1 www IN A 192.168.50.1 ftp IN A 192.168.50.1

5. Reverse zóna

sudo nano /var/named/50.168.192.rev
$TTL 1H @ IN SOA server.lab.test. admin.lab.test. ( 2026101401 1H 15M 1W 1H ) IN NS server.lab.test. 1 IN PTR server.lab.test.

6. Jogok, SELinux kontextus, ellenőrzés

sudo chown root:named /var/named/lab.test.zone /var/named/50.168.192.rev sudo chmod 640 /var/named/lab.test.zone /var/named/50.168.192.rev sudo restorecon -v /var/named/lab.test.zone /var/named/50.168.192.rev sudo named-checkconf sudo named-checkzone lab.test /var/named/lab.test.zone sudo named-checkzone 50.168.192.in-addr.arpa /var/named/50.168.192.rev

7. Indítás és tűzfal

sudo firewall-cmd --permanent --zone=internal --add-service=dns sudo firewall-cmd --reload sudo systemctl enable --now named dig @192.168.50.1 www.lab.test +short dig @192.168.50.1 -x 192.168.50.1 +short

8. Windows teszt

ipconfig /flushdns nslookup server.lab.test nslookup www.lab.test nslookup ftp.lab.test ping server.lab.test
Akkor jó: mindhárom név 192.168.50.1-re oldódik.
K16: named-checkconf / named-checkzone OK.
K17: Rocky dig válasz.
K18: Windows nslookup www.lab.test.
K19: Windows név szerinti ping.
6. modul • 45 perc

FTP – vsftpd és valódi jogosultságteszt

Elmélet: az FTP ebben a zárt laborban arra szolgál, hogy ugyanazokat a Linux fájl- és könyvtárjogokat hálózaton keresztül is megtapasztald. Valós hálózaton inkább SFTP-t használunk, mert az FTP nem titkosít.

1. Telepítés

sudo dnf -y install vsftpd sudo cp /etc/vsftpd/vsftpd.conf /etc/vsftpd/vsftpd.conf.orig

2. vsftpd konfiguráció

A laborhoz az /etc/vsftpd/vsftpd.conf legyen:

listen=YES listen_ipv6=NO anonymous_enable=NO local_enable=YES write_enable=YES local_umask=002 dirmessage_enable=YES use_localtime=YES xferlog_enable=YES connect_from_port_20=YES chroot_local_user=YES local_root=/srv/ftp pasv_enable=YES pasv_min_port=30000 pasv_max_port=30100 pam_service_name=vsftpd userlist_enable=YES

3. SELinux – laborbeállítás

getenforce getsebool -a | grep ftpd sudo setsebool -P ftpd_full_access on getsebool ftpd_full_access
Miért? ebben az oktatási laborban azt akarjuk, hogy a hozzáférést elsősorban a Unix owner/group/others jogosultságok határozzák meg, miközben SELinux továbbra is Enforcing marad. Éles rendszerben szűkebb SELinux policy és inkább SFTP javasolt.

4. Tűzfal és indítás

sudo firewall-cmd --permanent --zone=internal --add-service=ftp sudo firewall-cmd --permanent --zone=internal --add-port=30000-30100/tcp sudo firewall-cmd --reload sudo systemctl enable --now vsftpd sudo systemctl status vsftpd --no-pager sudo ss -lntp | grep :21

5. Windows 7 FTP teszt – anna

Hozz létre a Windows asztalon egy anna-win.txt fájlt. Ezután CMD:

ftp ftp.lab.test

Jelentkezz be anna felhasználóval, majd az FTP promptban:

dir cd anna put anna-win.txt cd .. cd kozos put anna-win.txt cd .. cd bela quit
Akkor jó: anna írhat az anna és kozos mappába, de a bela mappába nem léphet be.

6. vendeg negatív teszt

Jelentkezz be FTP-n vendeg felhasználóval. A nyilvanos mappát olvasni tudja, a kozos mappába viszont nem léphet be / nem írhat.

7. Ellenőrzés Rocky oldalon

sudo find /srv/ftp -maxdepth 2 -type f -printf '%M %u %g %p\n' sudo journalctl -u vsftpd --since "15 minutes ago" --no-pager
K20: vsftpd active + 21-es port.
K21: anna sikeres feltöltése saját mappába.
K22: anna sikeres feltöltése közös mappába.
K23: anna vagy vendeg szándékos Permission denied tesztje.
K24: Rocky oldali fájltulajdonos/csoport lista.

Apache webszolgáltatás és saját státuszoldal

Elmélet: az Apache HTTP Server alapértelmezetten a 80/TCP porton szolgál ki tartalmat. A DNS miatt a kliensnek nem kell az IP-címet megjegyeznie: a www.lab.test nevet használja.

1. Apache telepítés

sudo dnf -y install httpd sudo systemctl enable --now httpd sudo firewall-cmd --permanent --zone=internal --add-service=http sudo firewall-cmd --reload sudo systemctl status httpd --no-pager

2. Készíts egyszerű weboldalt

Nyisd meg: sudo nano /var/www/html/index.html, és készíts legalább ilyen tartalmú oldalt:

<!doctype html> <html lang="hu"> <head> <meta charset="utf-8"> <title>Rocky Linux labor</title> </head> <body> <h1>Rocky Linux 10.2 szerverlabor</h1> <p>Készítette: SAJÁT NÉV</p> <h2>Szolgáltatások</h2> <ul> <li>DHCP – Kea</li> <li>DNS – BIND</li> <li>FTP – vsftpd</li> <li>SSH – OpenSSH</li> <li>HTTP – Apache</li> </ul> </body> </html>

3. Helyi ellenőrzés

curl http://127.0.0.1 curl http://www.lab.test

4. Windows 7 böngésző

Nyisd meg:

http://www.lab.test
Akkor jó: a saját neveddel elkészített oldal jelenik meg.
K25: Apache active állapot.
K26: curl http://www.lab.test Rocky oldalon.
K27: Windows böngészőben a saját weboldal.
8. modul • 45 perc

firewalld, hibakeresés és teljes integrált ellenőrzés

Elmélet: a szolgáltatás attól még nem feltétlenül érhető el, hogy fut. A kliens → hálózat → tűzfal → daemon → alkalmazás teljes útvonalat kell ellenőrizni.

1. Nézd meg az internal zónát

sudo firewall-cmd --get-active-zones sudo firewall-cmd --zone=internal --list-all

Legalább ezekre számíts: ssh dhcp dns ftp http és a 30000-30100/tcp porttartomány.

2. Tudatos hibakísérlet – HTTP tiltása

sudo firewall-cmd --zone=internal --remove-service=http

Windows böngészőben frissítsd a http://www.lab.test oldalt. A kapcsolatnak meg kell szakadnia.

Állítsd vissza:

sudo firewall-cmd --zone=internal --add-service=http

Frissíts újra – az oldal működjön.

Figyelem: itt runtime szabályt módosítunk. A korábban megadott --permanent szabály továbbra is megmarad, ezért reboot/reload után a HTTP visszatér.

3. Szolgáltatások állapota

systemctl --no-pager --type=service --state=running | grep -E 'sshd|kea-dhcp4|named|vsftpd|httpd' sudo ss -lntup | grep -E ':22|:21|:53|:67|:80'

4. Windows teljes teszt

ipconfig /all ping server.lab.test nslookup www.lab.test nslookup ftp.lab.test

Ezután külön ellenőrizd:

  • PuTTY → server.lab.test
  • FTP → ftp.lab.test
  • Böngésző → http://www.lab.test

5. Hibakeresési sorrend

1. IP-cím?→2. Ping?→3. DNS?→4. service active?→5. port figyel?→6. firewalld?→7. log?
systemctl status SZOLGALTATAS journalctl -u SZOLGALTATAS --since "10 minutes ago" ss -lntup firewall-cmd --zone=internal --list-all
K28: teljes internal firewalld zóna.
K29: HTTP tiltás és visszaengedés bizonyítása.
K30: végső Windows képernyő: működő DNS + web/FTP/SSH közül legalább két kliensszolgáltatás.
